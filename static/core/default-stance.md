# Default Rendering Stance

- Scientific truth comes before photorealism.
- Start from a gray-box topology and refine only after interfaces and paths pass review.
- Use Blender when spatial placement and physical assembly matter; use editable SVG when the figure is primarily logical or temporal.
- Build reproducibly from scripts where practical, while using the application UI for visual inspection.
- Prefer a neutral light background or transparent master over a dark decorative scene.
- Use restrained materials, one coherent camera, broad lighting, and a small number of signal colors tied to physical meaning.
- Keep labels out of the base render. Add short horizontal text and direct vector leaders after geometry approval.
- Inspect output at full frame, manuscript width, slide width, and close crops of every critical junction.
- Prefer close-up evidence over a crowded overview for connector order, labels, switches, and cable seating.
- Treat projected visual ambiguity as a real defect: routes that are separated in depth may still form a misleading X-crossing in the final image.
- Keep every route inside a deliberate corridor and verify both endpoints, the complete route, and every bend or junction.
- A synthetic regression pass checks validator logic only. It never substitutes for project evidence or visual QA.
- Do not use reasonable assumptions for factual hardware or scientific details. Ask the user first; if they cannot answer, research authoritative sources; if the result remains uncertain, omit it or visibly mark it unresolved.
- Do not expose private local paths, filenames, credentials, or source materials in public-facing deliverables unless the user explicitly requests that audit trail.
- When publishing the skill itself, exclude project photographs, videos, papers, renders, `.blend` files, local paths, and project-specific logs; run the public-release audit before pushing.
